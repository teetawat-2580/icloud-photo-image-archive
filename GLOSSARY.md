# Domain Glossary — CloudVault Concierge

Canonical terminology shared across `web/`, `workbench/`, `workbench/cdp/`, and Supabase schema (`001_init_schema.sql`, `002_search_vault.sql`).

- **Concierge Job (`migration_job`)**: One isolated customer photo migration engagement identified by UUID `id` and human-readable `job_code` (e.g., `MIG-2026-0001`), bound to one `service_mode` (`copy_only`, `move_free_space`, `move_and_export`), target years, and a high-entropy URL token whose `SHA-256` hash is stored in `token_hash_sha256`.
- **Operator Node (`operator_node`)**: An authorized Operator Windows PC running `workbench/server.py` locally. Publishes ONLY its `RSA-4096` `public_key_pem` and `key_fingerprint_sha256` to Supabase while keeping `operator_private.pem` strictly offline.
- **E2E Credential Envelope (`credential_envelope`)**: A single-use JSON payload (`version`, `alg`, `key_fingerprint_sha256`, `wrapped_key_b64`, `iv_b64`, `ciphertext_b64`) encrypted client-side in the customer's browser via `RSA-OAEP-SHA256` + `AES-256-GCM`, with 15-min TTL and immediate `DELETE` upon RAM decryption by the Operator Workbench.
- **Interactive OTP Challenge (`otp_challenge`)**: A short-lived (`5-min TTL`) 2FA handshake row created by the Operator Workbench when Apple iCloud or Google prompts for a 6-digit code. The customer submits the code encrypted via the same E2E WebCrypto contract; the Workbench decrypts in RAM and immediately shreds the row.
- **Customer Sandbox (`D:\MigrationJobs\<job_id>\`)**: A path-confined local staging directory allocated strictly for one `job_id`, holding staging media (`Year/Month/IMG_XXXX`), manifest/checksum ledgers, isolated `.icloud_session`, and isolated `chrome_profile`.
- **Dedicated Chrome Automation Profile**: A per-job isolated Chromium instance launched with `--user-data-dir=<sandbox>\chrome_profile` and a dynamically assigned CDP port (`9301..9399`), yielding zero `Allow` prompts and zero cross-contamination with other customers or the operator's personal browser.
- **3-Layer Personal Album Isolation Guard**: Mandatory safety filter preventing a customer's personal Google Photos albums (any album outside `album_prefix`) from mixing with migrated iCloud archive albums (`Layer 1: Personal Album Blacklist`, `Layer 2: Zero Blind Day-Level Select-All`, `Layer 3: 1:1 Manifest Exact-Second Timestamp & Filename Whitelist`).
- **5-Lock Space Reclaim**: Fail-closed iCloud cleanup protocol requiring all 5 checks (`100% Uploaded`, `100% 64-char SHA-256`, `1:1 CloudKit ID & Filename`, `Whole-Year Completeness`, and `Customer Portal Sign-Off + 30-Day Recently Deleted Soft-Delete`) before setting `isDeleted = 1`.
- **PDPA Purge Certificate**: An RSA-PSS-SHA256 signed immutable JSON record persisted to `migration_jobs.pdpa_purge_certificate` proving that all local media, `.icloud_session`, and `chrome_profile` artifacts for a `job_id` were verified wiped (`remaining_files = 0`, `remaining_bytes = 0`).
- **Zero-Knowledge Search Vault (`search_vault`)**: An encrypted, customer-owned AI photo search index persisted in `public.search_vaults` (metadata/public key/encrypted private key blob) plus Cloudflare R2 or PC Tunnel NAS (opaque `.enc` WebP thumbnails and gzipped index bundle), decryptable exclusively inside the customer's browser RAM.
- **One-Way Public-Key E2EE**: Cryptographic publishing pattern where the Operator PC wraps a fresh 32-byte `vault_data_key` using ONLY the customer's `RSA-OAEP(SHA-256)` public key, encrypts all thumbnails and search index payloads, zeroes the key in RAM, and purges plaintext temp media — guaranteeing neither the PC owner nor cloud servers can read the vault at rest.
- **Client-Side Encrypted Index Bundle (`index_bundle.json.gz.enc`)**: A gzip-compressed JSON bundle containing face clusters, Thai/English OCR text, pre-computed semantic tags, dates, and pluggable media references, encrypted with `AES-256-GCM` (`AAD = "${vaultId}:index_bundle"`) and queried exclusively inside browser RAM (`< 20 ms`).
- **Pluggable Media Source Adapter**: Indirection contract keying every indexed photo by immutable `sha256` + `filename` + `captured_at` rather than a hard-coded storage URL, enabling zero-reindex migration between `google_photos_shared`, `google_photos_private`, `nas_immich`, and `local_hdd`.
- **Encrypted Person Labels (`encrypted_person_labels_blob`)**: Customer-authored face cluster display names (e.g., `person_001 -> "คุณแม่"`) encrypted in browser RAM with `AES-256-GCM` (`AAD = "${vaultId}:person_labels"`) prior to storage in Supabase.
